# 文章の書き方 (全 TORO リポジトリ共通)

TORO のすべてのリポジトリの文書は、将来だれでも読める形で公開されます。TORO の内部を知らない人が読んでも分かるように書きます。
この文書が、文章の書き方のただ 1 つの正本です。各リポジトリの文書には、この内容を写さず、ここへリンクしてください。

## 守ること

1. **ふつうの言葉で書く。** 業界用語・略語・カタカナの専門語・仲間うちの造語は使いません。使う必要があるときは、初めて出る場所で短く説明します。
2. **略さない。** 「版」だけで「バージョン」を表さず、「バージョン」と書きます。
3. **言い換える例。**
   - リポジトリ → 「プログラムや文書の置き場」(GitHub の画面の名前としてのみ、そのまま使ってよい)
   - デプロイ → 「公開する」「動かせる状態にする」
   - ロールバック → 「元に戻す」
   - SSOT → 「正本 (ただ 1 つの元になる場所)」
   - プレースホルダー → 「後で書き換える仮の値」
4. **そのまま書いてよいもの。** 固有名詞、コマンド名、ファイル名、バージョン番号そのもの (例: v1.2.1)。
5. **「窓口」は使わない。** 意味があいまいな造語のためです。「コネクタ」「API」「受付フォーム」など、指すものを正確に書きます。
6. **内部の運用用語を書かない。** 運用側だけで通じる呼び名は、公開文書に出しません。

## 書いてはいけないもの

- パスワード・トークン・鍵などの秘密、ホスト名・IP アドレス・ポートの公開範囲、自分のパソコン上の絶対パス、Discord のチャンネル ID などの識別子、個人を特定できる名前。
  必要なときは変数名や `<値>` のような仮の書き方にし、本当の値は環境変数など、リポジトリの外に置きます。
- 日付つきの確認記録や「現在は〜」「まだ〜していない」のような、時間とともに古くなる文。履歴は Git の履歴・CHANGELOG・リリースノートが持ちます。
- ライセンスの節。ライセンスはリポジトリ直下の `LICENSE` ファイルだけで示します。

## 文書の役割

| 書く内容 | 置き場所 (1 か所だけ) |
| --- | --- |
| 概要・目的・最小の始め方 | `README.md` |
| 設定の既定値・環境変数 | コード、または設定のサンプルファイル |
| API の仕様 | コード (OpenAPI など) か、`docs/` の専用ファイル 1 つ |
| 運用の手順 | `docs/RUNBOOK.md` など 1 つ |
| バージョン | Git のタグとリリース |
| 変更の記録 | `CHANGELOG.md`・リリースノート |
